# Phase 5 — public docs and community mechanics

**Date: 2026-08-19.** The phase-5 session of the release plan
(`docs/analysis/2026-08-18-release-phase-brainstorm.md`). Most of the phase's original
list had already landed with phases 1–4 (the guide moved with every surface change; the
README and process docs were truth-synced at each increment), so this session carried the
three remaining owner decisions and their landings, plus the consolidated release-day
checklist the phase-0 record asked this phase to produce.

## The rulings and what landed under them

1. **The api-reference drift gate is built.** `pnpm api-sync`
   (`scripts/api-reference-sync.mjs`, with its own parsing pins under `scripts/test/`)
   fails when any name `packages/record/src/index.ts` exports does not occur, as a whole
   word, in `docs/guide/api-reference.md` — the one mechanical check behind the PR
   template's existing checkbox, run in CI's checks job beside the contract scan. Its
   bounds are stated in its header: presence, never accuracy; record's entry point only;
   one-directional by design (the reference legitimately names non-exported things).
   **Its first live run found five real drift items** — `OpenOptions`/`FinalizeOptions`'s
   input types (`ConsultationInput`, `ObtainedConsultation`, `UnreachableMarker`,
   `PolicyInput`, `PriorRecordRef`) were exported at the phase-1 review but never
   enumerated in the reference — now documented with their exact source shapes, and the
   gate is green.
2. **The copyright landed as a NOTICE file.** Root `NOTICE` ("Copyright 2026 The Vidimera
   Authors"), copied into both packages and added to their `files` arrays — Apache-2.0's
   own preservation mechanism. The LICENSE appendix stays stock (instructional text, not
   the declaration); the manifests already carry `author` and `license`.
3. **Both packages publish at the 0.1 cut.** The release workflow's guard now checks both
   manifests, and publishing goes tarball-first (`pnpm pack`, then
   `npm publish <tarball> --provenance`) in order — `record` before the adapter that
   peer-depends on it — so the adapter's `workspace:*` peer range is rewritten to the
   real version at pack time. A 0.1 whose docs name `PostgresStore` but whose registry
   lacks it would be the claims-versus-delivery gap this plan exists to prevent.

## Also landed

- `.github/ISSUE_TEMPLATE/config.yml` — blank issues off, security reports routed to
  private vulnerability reporting (the file half of phase 0's contact ruling; the
  repository *setting* stays a release-day checkbox).
- `docs/process/release-checklist.md` — the one authoritative release-day list:
  preconditions, the phase-0 floor rule, the file changes, the three settings no commit
  can land, the dispatch, the post-publish verification and paperwork.
- README and CONTRIBUTING dev blocks now name every gate (`build`, `smoke`, `api-sync`,
  and the strict lint CI enforces); CLAUDE.md's commands and CI descriptions moved with
  them.

## What phase 5 leaves for phase 6 and release day

Phase 6 is the first-use validation: one documented, reproduced run from packed artifact
to verified chain on a machine that never held this checkout — the checklist's own first
precondition. Release day itself is the checklist, top to bottom; register row 1 retires
when its workflow has run once.
