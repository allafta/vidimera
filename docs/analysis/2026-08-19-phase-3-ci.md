# Phase 3 — CI and infrastructure hardening

**Date: 2026-08-19.** The phase-3 session of the release plan
(`docs/analysis/2026-08-18-release-phase-brainstorm.md`). Four rulings by the repository
owner; everything landed in this increment. Register row 5 retired here — its trigger
fired deliberately rather than tripped.

## The rulings

1. **The CI matrix: floor + current + three OSes.** `.github/workflows/ci.yml` is now
   two-tier: a Linux `checks` job runs the platform-independent gates once (typecheck,
   lint, contract-scan, `lint:strict`), and a `test` matrix runs test + build + the
   packed-tarball smoke test on four combinations — ubuntu @ **22.16.0** (the exact
   declared engines floor, which `node-version: 22` alone never tests — the standing
   lesson that a floor declared but never exercised is a claim with no gate), ubuntu @ 24
   (current), and windows/macos @ 22 (this repository is developed on Windows;
   `node:sqlite` and `npm pack` are the platform-sensitive parts, and neither had ever run
   in CI off Linux). `pnpm/action-setup` + setup-node's pnpm cache replace the bare
   corepack step, in both CI and the release workflow. The five-job total is a deliberate
   bound: the marginal combinations (macos @ floor, windows @ 24) were judged unlikely to
   catch anything this shape misses.

2. **Row 5 fired deliberately and retired.** The row's own retriggering history is why:
   its original trigger fired twice with nobody noticing, and a lint-infrastructure phase
   walking past an armed file-edit trigger is how that happens a third time. Executed
   exactly as the row's dry-run predicted — one hunk, `"recommended": true` →
   `"preset": "recommended"` — plus the hand-added `$schema` (node_modules-relative, so
   no external URL and no version pin to drift) the row recorded migrate would not add.
   `pnpm lint` output: 14 infos → 13, the deprecation notice gone; `lint:strict` exit 0.

3. **Dependabot, weekly, grouped.** `.github/dependabot.yml`: npm (the four root
   devDependencies) and github-actions ecosystems, one grouped PR each per week at most.
   The full CI gate set — smoke test included — is what makes these safe to review
   quickly.

4. **CODEOWNERS guards the sealed set.** `.github/CODEOWNERS` requires the owner's review
   on `docs/concept/` and on the frozen byte-stability test — the repository's two
   never-touch-without-sanction surfaces, made mechanical for pull requests. Advisory
   until the require-review-from-code-owners branch protection is enabled: a repository
   setting, added to the release-day checklist beside phase 0's (private vulnerability
   reporting, the Node-floor re-evaluation, the CLAUDE.md skim, dropping `private: true`,
   the npm scope and `NPM_TOKEN` secret).

## Honest bounds, in the same breath

The matrix workflow is authored but validates only on an actual push — no local runner
executes GitHub Actions here, so windows/macos and the exact-floor job are exercised the
first time CI runs this tree. The smoke test and full suite were re-run locally (Windows,
Node 24) before commit; the workflow YAML itself is the untested surface until then.
CODEOWNERS enforces nothing until the branch-protection setting is enabled, and Dependabot
opens nothing until the repository is on GitHub with the file on the default branch.

## Addendum, 2026-09-03 — the test gate this record installed was inert

This record is a dated artefact and its body stands as written. What it could not know: the
`pnpm test` step of the matrix it installed concluded success for every failed run, on every
leg, from the day the adapter's suite joined the workspace until the CI test-gate repair of
2026-09-03. The cause was not the workflow — `embedded-postgres` registers an `async-exit-hook`
handler at module load whose `beforeExit` listener exits 0 over the exit code vitest had set,
and the adapter's vitest global setup imported the library in vitest's main process. A canary
pull request with one always-failing test showed four green test legs (run 33705059031). The
line above about "a floor declared but never exercised" being "a claim with no gate" applied,
for those three weeks, to the gate itself: nothing had ever turned it red, and a passing gate
looks identical to an inert one. The repair, its proof in two deliberately red runs, and the
independent report gate that now reads vitest's own JSON are recorded in
`docs/process/implementation-status.md` (the CI test-gate repair section); the discipline it
left — a gate is evidence only once it has been seen to fail — is in
`docs/process/next-phases.md`. The typecheck, lint, contract-scan, api-sync, docs-index-sync,
build, and smoke steps were each shown to exit non-zero on their own failure class the same
day, so the `checks` job and the rest of the `test` legs were never inert in this way; only
the suite's exit code was.
